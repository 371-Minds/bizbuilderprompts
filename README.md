# AI Agent Integrated Repository for ElizaOS

This repository contains prompts and project templates for AI agents operating within our internal ElizaOS ecosystem. This guide outlines the architecture, workflow, and best practices for agents interacting with this codebase.

## System Overview

Our AI agents operate on a custom platform that leverages Akash for decentralized LLM inference and ElizaOS for knowledge access and contextual understanding.

### ElizaOS Integration

To effectively assist users, AI agents must connect to the ElizaOS instance. This provides access to a shared knowledge base, including user research, notes, and goals. This connection is crucial for agents to make informed, proactive, and personalized decisions. As seen in prompts like `run_mini_dao_agent/4_insight_integration.md`, agents are expected to seamlessly weave insights from ElizaOS into their guidance without explicitly stating the source of the information.

## Repository Structure

*   **/run_***: These directories contain sequences of prompts that define agent workflows for specific tasks (e.g., `run_alchemist_apprenticeship`, `run_venture_forge`). Each file within these directories represents a step in the workflow.
*   **/projects**: This directory is the designated output location for agent-generated content, code, and other artifacts.

## AI Agent Workflow

1.  **Trigger**: An agent is activated by a user request or a system event.
2.  **Context Gathering**: The agent connects with ElizaOS to gather relevant context about the user, task, and project.
3.  **Prompt Selection**: The agent selects the appropriate prompt or sequence of prompts from the `/run_*` directories based on the task.
4.  **Inference**: The agent sends the populated prompt to a Large Language Model for processing via our Akash-based inference service.
5.  **Action**: The agent processes the LLM's response to perform an action. This may include writing a file to the `/projects` directory, calling another tool, or responding to the user.

## Prompting Guide for Agents

The prompts in this repository are carefully engineered. Agents should pay close attention to the structure of each prompt, which typically includes:

*   **Trigger**: The condition that activates the prompt.
*   **Your Task**: A clear description of the agent's objective.
*   **Persona**: The desired personality and communication style for the agent.

For a deep dive into the advanced prompt engineering techniques used here, agents should refer to the analysis in `run_dsf_playbook/resources/Evaluation of Meta-Prompt v4.3.txt`.

### Prompting Best Practices

When interacting with the LLMs via Akash, agents should consider the following best practices:

*   **System Instructions**: Use system-level instructions or a preamble to steer the model's behavior and define its role before it receives user-specific instructions.
*   **Response Schema**: When structured data is required, specify the desired output schema (e.g., JSON) in the prompt to ensure reliable and parsable responses.
*   **Safety Settings**: Be mindful of the content being generated and adhere to internal safety guidelines. Adjust inference parameters if the underlying model supports it to manage harmful responses.

### Secure Execution Layer

Our "secure sandbox" for AI agents enforces the "principle of least privilege" to minimize security risks. This includes:

*   Container-based isolation for each agent.
*   Resource limitations to prevent service disruptions.
*   Restricted network access.
*   Fine-grained API permissions and just-in-time credential provisioning.
*   Real-time monitoring and anomaly detection of agent activities.
